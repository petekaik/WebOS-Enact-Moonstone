Developing Apps for LG OLED65C8 (webOS TV 4.x)

The LG OLED65C8 (2018) runs webOS TV 4.x. Its web engine is Chromium 53 (approximately Chrome 53) (webostv.developer.lge.com), so modern JavaScript and CSS may require transpilation/polyfills. LG’s current SDK and tools support webOS 4.x apps, and the recommended approach uses the webOS CLI (ares) with Node.js. This guide covers the latest SDK/CLI, compatible frameworks, setup steps, and a “Hello World” tutorial using VSCode and Node.js on a local machine.

Official SDKs, CLI Tools, and Frameworks

LG’s webOS development now centers on the webOS CLI (formerly called ares). The older “webOS TV CLI” (part of legacy SDKs) was deprecated in 2024. In fact, LG states: “we decided to no longer support webOS TV CLI from March, 2024. We recommend that you use the webOS CLI instead.” (webostv.developer.lge.com) (webostv.developer.lge.com). The webOS CLI is distributed via npm as @webos-tools/cli. Install it with Node.js (LTS v16 or later):

  npm install -g @webos-tools/cli

After installation, verify with ares -V. The CLI has been tested on Node.js v14 and v16 (github.com), so using a current LTS (v16 or v18) is safest. LG recommends always using the latest CLI version, which is backward-compatible with webOS TV 4.x (and newer) (github.com).

  • Node.js: Use the latest LTS release (v16 or v18). The webOS CLI has been tested on Node v14.15.1 and v16.20.2 (github.com).
  • webOS CLI: Install with npm as above (webostv.developer.lge.com). This replaces the old webOS Studio/IDE. (The older CLI downloads for Windows/macOS are deprecated.)
  • Device Connection: The CLI includes ares-setup-device and ares-novacom to add and authenticate your TV.

No official LG emulator is recommended for webOS 4.x; the legacy Simulator (from WebOS Studio) is deprecated. Testing should be done on a real TV (or the newer webOS OSE emulator, which targets Open-Source Edition on hardware like Raspberry Pi).

Frontend Frameworks and Libraries

webOS TV apps are just HTML/CSS/JS; you can use any framework that outputs compatible code. LG’s official UI framework is Enact (a React-based SDK) which provides TV-tailored components (e.g. Moonstone theme, spotlight navigation) and a webOS support library (enactjs.com). Enact apps use React/JSX and are built with webpack/Babel, producing ES5 code for older engines. Using Enact is recommended for larger apps, but not required.

Other options:

  • Vanilla or PWA: You can write a simple HTML/JS app. Ensure you avoid unsupported features or use a transpiler. For example, ES6 classes or modules may need Babel, since webOS 4.x’s Chromium 53 does not support all ES2015+ features.
  • Third-party frameworks: Angular, Vue, Svelte, etc. can be used if you bundle/transpile their output to ES5. The app is packaged as a static bundle anyway. Note that older web engines may lack features like modern CSS grid or Flexbox; test accordingly.
  • LG webOS libraries: If your app needs to call TV APIs (e.g. Luna services), use LG’s webos service libraries from Enact (e.g. webos/service) or webos.js. These simplify interactions with the TV (launching channels, getting system info, etc).

For example, Enact’s packages include moonstone (TV UI components) and webos (service APIs) (enactjs.com). When future-proofing, note that newer webOS versions (5.x, 6.x, 22 etc.) use more recent Chromium (68, 79, 87, etc. as shown in the table webostv.developer.lge.com), so code written for 4.x should also work on newer TVs. Always test on your target OS version.

Setting Up the Development Environment

1. Install Node.js and the webOS CLI

On your development PC (Windows/Linux/macOS), install Node.js (download from nodejs.org). Then open a terminal and install the webOS CLI:

  npm install -g @webos-tools/cli

After installing, confirm the CLI is available:

  ares -V

You should see a version number (1.12.4 or later). If you have an old webOS OSE or TV CLI installed, remove it first (e.g. npm uninstall -g @webosose/ares-cli) to avoid conflicts (webostv.developer.lge.com).

2. Enable Developer Mode on the TV

Using Volta to Manage Node.js Versions

If your system Node.js version is too new (e.g., v22), you can use Volta, a Node.js version manager, to install and pin an older compatible version like v16 for your webOS development project.

  1. Install Volta: Open your terminal and run: 
    curl https://get.volta.sh | bash
    Restart your terminal to ensure Volta is available.
  2. Install Node.js v16: 
    volta install node@16
    This installs Node.js v16 and makes it available via Volta.
  3. Create a package.json file: Volta requires a package.json file to pin Node versions. If it doesn't exist yet in your project directory, create one by running: 
    npm init -y
    This generates a default package.json file.
  4. Pin Node.js to the project: With a package.json file present, pin the version using: 
    volta pin node@16
    This pins the Node version for the project and updates package.json under a "volta" field.
  5. Verify the Node version: 
    node -v
volta list
    The output should show Node v16.x.x as the current version, and confirm that it is pinned for the project.

Now, all Node.js and npm commands in this project directory will use Node v16, regardless of your system-wide version. This avoids compatibility issues with the webOS CLI and Enact tooling.

To deploy apps, your TV must be in Developer Mode. Steps:

  • Developer Account: Create an LG Developer account at webOS TV Developer. (This is used to log into the Developer Mode app.)
  • Developer Mode App: On the TV, open the LG Content Store and search for “Developer Mode.” Install and launch it.
  • Login & Enable: In the Developer Mode app on the TV, sign in with your LG account. Turn on Developer Mode and enable the Key Server. The TV will reboot.
  • Passphrase: After reboot, open Developer Mode again. Make sure “Dev Mode Status” is ON and note the passphrase displayed on screen.

Now the TV is ready to accept sideloaded apps. The developer guide notes that for webOS TV 3.0 and above, you test on the actual device via the Developer Mode app (webostv.developer.lge.com).

3. Connect the CLI to the TV

Ensure your PC and TV are on the same local network. On your PC:

  • Add the TV as a device: Choose a name (e.g. myTV) and run:
    •     ares-setup-device --add myTV -i "host=TV_IP_address" -i "port=9922" -i "username=developer"

    (Replace TV_IP_address with your TV’s IP; port is usually 9922; the SSH user is developer.) LG’s docs give an example format (webostv.developer.lge.com).

  • Retrieve the developer key: Run:
    •     ares-novacom --device myTV --getkey

    This initiates a key exchange. Enter the passphrase you saw on the TV’s Developer Mode screen. This command “gets a private key from webOS TV for the Developer Mode app,” allowing the CLI to sign and install apps (webostv.developer.lge.com).

  • Verify the connection (optional): Check if the device responds:
    •     ares-device-info --device myTV

    You should see device info (model, version). If there are errors, re-check the IP, network, and passphrase.

Hello World App: Step-by-Step Guide

Getting Available Versions for Enact CLI

To find all available versions of the Enact CLI, use the following npm command:

  npm show @enact/cli versions --json

This will output a JSON array of all published versions. For Enact v1.13, the latest compatible CLI version is 1.13.4.

Installing Enact CLI Version 1.13.4

To install the compatible version of Enact CLI, use the following command:

  npm install -g @enact/cli@1.13.4

This ensures compatibility with Enact v1.13 and webOS TV 4.x.

To verify the installed version of Enact CLI, run:

  enact --version

The output should display 1.13.4.

Installing a Known Supported Version of Enact CLI

Once you identify the compatible version, install it using the following command:

  npm install -g @enact/cli@1.2.3

Replace 1.2.3 with the desired version number. This ensures compatibility with the latest Enact v1.x framework.

To verify the installed version of Enact CLI, run:

  enact --version

The output should display the version you installed.

Ensuring Compatible Enact CLI Versions for Enact 1.x Projects

Enact 1.x projects are best supported using an older version of the Enact CLI that matches the framework version. Using newer CLI versions (such as 6.x or 7.x) may cause compatibility issues due to changes in dependencies and React versions.

  1. Determine a compatible Enact CLI version: For Enact 1.x, use a CLI version released around the same timeframe, typically version 1.x or 2.x. For example: 
    npm install --save-dev @enact/cli@1.2.3
    Replace 1.2.3 with the appropriate version matching your framework.
  2. Use the local CLI installation with npm scripts: Add CLI commands to package.json: 
    {
  "scripts": {
    "serve": "enact serve",
    "pack": "enact pack"
  }
}
    This ensures that local CLI versions are used instead of any globally installed ones.
  3. Run Enact commands using npm: 
    npm run serve
npm run pack
  4. Verify installed versions: 
    npm list @enact/cli
npm list @enact/core
    Confirm these match your intended Enact and CLI versions.

Always use project-local Enact CLI installations for reproducibility and version control. Avoid using globally installed CLI versions when working with older framework releases.

With the environment ready, create a simple app. In your terminal:

  1. Create a project directory: Use the CLI template. For a basic web app: 
          ares-generate -t basic HelloWorld
    This makes a HelloWorld/ folder containing appinfo.json, index.html, and other starter files.
  2. Edit the app files: Open HelloWorld/appinfo.json in VSCode. Set a unique id, and ensure main and title are correct. For example: 
    {
  "id": "com.example.helloworld",
  "version": "1.0.0",
  "title": "HelloWorld",
  "type": "web",
  "main": "index.html",
  "icon": "icon.png"
}
    Replace com.example.helloworld with your own namespace. Next, edit index.html (in the same folder) to show something visible: 
    <!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>HelloWorld</title>
</head>
<body>
  <h1>Hello, webOS TV!</h1>
</body>
</html>
    Save the files.
  3. Package the app: Still in the terminal, from the directory above HelloWorld/, run: 
          ares-package ./HelloWorld
    The CLI reads appinfo.json and creates HelloWorld_1.0.0_all.ipk in the current folder. (It minifies/merges files by default.)
  4. Install the app on TV: Send the IPK to the TV: 
          ares-install --device myTV HelloWorld_1.0.0_all.ipk
    The CLI installs the app via SSH. On success, you should see a confirmation. (If you encounter errors, ensure Dev Mode is on and the TV is reachable.)
  5. Launch the app: Run it on the TV: 
          ares-launch --device myTV com.example.helloworld
    Replace the app ID if different. The CLI will launch the app on the TV (webostv.developer.lge.com). You should see your “Hello, webOS TV!” message on the screen.
  6. Debug or Inspect (optional): While the app is running, you can open a debugger on your PC: 
          ares-inspect --device myTV --app com.example.helloworld --open
    This opens a browser Web Inspector (Chrome DevTools) to debug the app’s HTML/JS in real time (webostv.developer.lge.com). This is useful for logging or fixing layout issues.

3. Install the Moonstone Template

To create a new Enact app using the Moonstone template, you need to install the template manually if it is not available by default. Run the following command:

  enact template install @enact/template-moonstone

Once installed, you can create a new app using the Moonstone template:

  enact create --template moonstone MyApp

This will generate a complete app with React, Babel, Moonstone components, and Webpack configuration.

Navigate to the project directory and run the app locally:

  cd MyApp
npm run serve

Visit http://localhost:8080 in your browser to confirm it runs.

Using Enact, Moonstone, and Babel: Full Project Setup

  1. Install Enact CLI: Globally install Enact CLI, which sets up React + Moonstone projects. 
    npm install -g @enact/cli
  2. Create a new Enact app using the Moonstone template: 
    enact create --template moonstone enact-hello
    This generates a complete app with React, Babel, Moonstone components, and Webpack configuration.
  3. Run the app locally: Test the build with: 
    cd enact-hello
npm run serve
    Visit http://localhost:8080 in your browser to confirm it runs.
  4. Edit the main panel to show Hello World: Modify src/views/MainPanel.js: 
    import kind from '@enact/core/kind';
import React from 'react';
import {Header, Panel} from '@enact/moonstone/Panels';
import BodyText from '@enact/moonstone/BodyText';
import Button from '@enact/moonstone/Button';

const MainPanel = kind({
  name: 'MainPanel',
  render: () => (
    <Panel>
      <Header title="Hello World" />
      <BodyText>This is a webOS TV app using Enact.</BodyText>
      <Button onClick={() => alert('Hello')}>Click Me</Button>
    </Panel>
  )
});

export default MainPanel;
  5. Build the app: Create a production build for packaging. 
    npm run pack
    Output will go into the dist/ directory.
  6. Create an appinfo.json file in the dist folder: Required for webOS packaging. 
    {
  "id": "com.example.enacthello",
  "version": "1.0.0",
  "title": "Enact Hello",
  "type": "web",
  "main": "index.html",
  "icon": "icon.png"
}
  7. Package the app: 
    ares-package dist
  8. Install and launch the app on the TV: 
    ares-install --device myTV dist_1.0.0_all.ipk
ares-launch --device myTV com.example.enacthello

This process uses Babel for JSX/ES6 transpilation, Webpack for bundling, and Moonstone for UI components. You can now begin expanding your Enact project with more views and components.
